# XW16Pro 扩展串口控制协议

> **来源**：《XW16Pro 脱机编程器用户手册》（2024-09-29 版，www.xwopen.com）第 10 章
> **适用范围**：通过 FT232/CH340T 扩展串口控制 XW16Pro 脱机编程器（启动烧录、查询结果、清除结果）

---

## 1. 概览

编程器的 **USB 主机接口**插入一块 FT232/CH340T 主控的 USB 转串口板/线后，即获得一个扩展串口。外部控制器（电脑串口、PLC、工控机等）通过串口线连接该转串口板的串口端，即可向编程器发送指令：

- **启动烧录**（指定镜像号、指定通道，可携带条码数据）
- **查询上次烧录结果**（镜像号、主校验和、剩余次数、成功/失败）
- **UID 扩展查询**（额外返回上次烧录芯片的 UID，用于动态数据加密）
- **清除上次烧录结果**

支持**序列号寻址**与**广播寻址**：多台编程器的扩展串口可并联统一接收命令，据命令中的地址信息决定全体同时启动、某台某通道启动、或某台反馈结果。

---

## 2. 硬件与连接要求

- USB 主机接口实现了对 **FT232** 及国产 **CH340T** 的驱动（芯片**默认 VID/PID**，**不支持 OEM 类** USB 转串口）。
- 市场上有 TTL 电平与 RS232 电平两种转串口板/线，均可使用，按需采购。
- 建议优先使用**带晶振**的 FT232 转串口板/线（长期稳定性与时序精度优于无晶振版本）。
- **编程器仅在烧录界面才会尝试连接 USB 转串口外设**；连接成功后界面显示"USB 串口正常"。
- 多台并联时，各编程器扩展串口可全部接在一起统一接收命令；查询命令只有目标编程器回复。

---

## 3. 默认串口通信参数

| 参数 | 值 |
|---|---|
| 波特率 | 9600 |
| 数据位 | 8 |
| 校验位 | 无（N） |
| 停止位 | 1 |

即 **9600-8-N-1**。

---

## 4. 通用规则（所有串口命令）

1. **命令起始符 `` ` ``**：第 1 位固定为反引号。编程器**任何时候收到 `` ` `` 都会放弃之前接收的所有字符，重新开始接收**。
2. **结束符 `\n`**：编程器收到 `\n` 后开始解析命令；命令有效则执行。
3. **可忽略字符**：命令中出现 `|` 或 `\r` 会被无视（用于人工可读的分隔，等价于不发送）。
4. **非法字符判定**：除 `` ` ``、命令字（`P`/`C`/`U`/`F`）、`0`-`9`、`a`-`f`、`A`-`F`、`\r`、`|` 之外的任何字符，都会使命令**无效**。
5. **序列号字段**：目标编程器序列号为十进制，**8 位定长，不足补 0**；`88888888` 为**广播地址**，所有编程器均响应。

---

## 5. 启动烧录命令（`P`）

```
`P + 序列号(8位) + 通道掩码(8位) + 镜像号(4位) + [条码hex，可省略] + \n
```

**示例**（竖线仅为可读性，可省略）：

```
`P00881289|00000001|0765|30313233333536\r\n
```

等价于：

```
`P0088128900000001076530313233333536\n
```

**字段解析**：

| 字段 | 长度 | 说明 |
|---|---|---|
| `` ` `` | 1 | 命令起始符，不可省略 |
| `P` | 1 | 固定命令字，必须为 `P` |
| `00881289` | 8 | 目标编程器序列号（十进制），此处为 881289；单烧录器也可用广播地址 `88888888` |
| `00000001` | 8 | **通道掩码**，32 位十六进制数，从最低位起依次为 A、B、C、D…通道的使能标记：`00000001` = A 通道，`00000002` = B 通道 |
| `0765` | 4 | 要烧录的镜像号（十进制），此处为 765 号镜像 |
| `30313233333536` | 可变 | 条码值：**以 ASCII 表示的十六进制数，两位表示一个条码字节**。此处表示把 `{0x30,0x31,0x32,0x33,0x33,0x35,0x36}` 写到镜像配置的条码地址，写入大小端与镜像配置相关；用不到可省略 |
| `\n` | 1 | 结束符，收到后解析并启动烧录，不可省略 |

### 5.1 镜像选择与自动切换

编程器内部按**镜像号**索引已注入的程序镜像：`P` 命令的镜像号字段即指定本次烧录使用的镜像，
**无需在编程器菜单中手动切换**——收到带有效镜像号的 `P` 命令后，编程器自动选择该镜像并执行烧录
（真机实测确认：换镜像号字段即换烧录程序，如 `0765` → `0766`）。

- 同一镜像号在同一时刻对应唯一程序；烧录不同程序只需更换命令中的镜像号字段。
- 镜像号必须在编程器中已注入（手册第 3、14 章），否则烧录失败。
- 双通道烧同一程序时，需把程序配置到两个不同镜像号位置（见 9.3）。

## 6. 查询上次烧录结果命令（`C`）

```
主机发送：`C + 序列号(8位) + 通道掩码(8位) + \n
```

**示例**：

```
`C00881289|00000001\r\n        （等价 `C0088128900000001\n）
```

**编程器回复**：

```
`C + 序列号(8) + 通道掩码(8) + 镜像号(4) + 主校验和(8) + 剩余次数(16) + 结果(1) + \r\n
```

**回复示例**：

```
`C00881289|00000001|0765|0A38AEF0|FFFFFFFFFFFFFFFF|0\r\n
```

**回复字段解析**：

| 字段 | 说明 |
|---|---|
| `0765` | 上次烧录的镜像号；返回 `9999` = 开机后此通道还没烧录过芯片 |
| `0A38AEF0` | 上次烧录镜像的**主校验和**（十六进制）；返回 `FFFFFFFF` = 开机后未烧录过 |
| `FFFFFFFFFFFFFFFF` | 上次烧录镜像的**剩余次数**（十六进制）；返回 `FFFFFFFFFFFFFFFF` = 无限次或开机后未烧录过 |
| `0` | 烧录结果：`0` = 成功，`1` = 失败，`2` = 结果被清空过，`3` = 开机后此通道没烧录过也没被清空过 |

---

## 7. UID 扩展查询命令（`U`）— 需固件 > 20240103000000

> 与 `C` 命令功能基本一样，但可额外查到**上次烧录芯片的 UID 值**，做动态数据加密时可用此功能。**固件版本需大于 20240103000000 才支持。**

```
主机发送：`U + 序列号(8位) + 通道掩码(8位) + \n
```

**回复示例**：

```
`U00881289|00000001|0000|00000000|FFFFFFFFFFFFFFFF|0|0C31FF410B3342393631540443000000000000000000000000\r\n
```

**回复字段解析**：前 6 段与 `C` 命令相同（镜像号/主校验和/剩余次数/结果）。

第 7 段为 **UID 数据区，长度固定 50 个字符**：

- 前 2 位：上次烧录芯片的 **UID 长度**（十六进制字节数）。如 `0C` = 0x0C = 12 字节。
- 随后跟的 12 字节即为**有效 UID 数据**：`31 FF 41 0B 33 42 39 36 31 54 04 43`。
- 再后面的值无论是什么，均无意义。

---

## 8. 清除上次结果命令（`F`）

```
主机发送：`F + 序列号(8位) + 通道掩码(8位) + \n
```

**示例**：

```
`F00881289|00000001\r\n
```

- 清除指定通道上次烧录的结果；**全通道清空时通道掩码填 `FFFFFFFF`**。
- 若使用广播地址 `88888888`，所有收到命令的编程器均按指令清空指定通道的结果。

## 9. 注意事项汇总

### 9.1 界面状态要求（最容易踩坑）

| 操作 | 编程器必须处于 |
|---|---|
| 与电脑（USB 从机）通信、注入/导出镜像、固件升级 | **菜单界面** |
| 连接 USB 转串口外设、响应串口控制命令 | **烧录界面** |

### 9.2 命令格式

1. 所有命令必须以 `` ` `` 开头、以 `\n` 结尾；缺少任一部分命令不生效。
2. 收到 `` ` `` 即重置接收状态，丢弃此前所有字符——**不要在一条命令前发送无关字符**（会被当作命令体的一部分使命令无效，除非是白名单字符）。
3. 除 `` ` ``、命令字、`0-9`、`a-f`、`A-F`、`\r`、`|` 外的字符会使命令无效。
4. 条码字段是 **ASCII 表示的十六进制**（不是原始二进制），两位表示一个字节；大小端与镜像配置相关。

### 9.3 通道与镜像

5. **B 通道的串口命令仅在开启双通道模式时才会执行**；单通道模式下只响应锁定通道的命令。
6. 双通道禁止烧录同一镜像号的镜像——需要双通道烧同一程序时，把程序配置到两个不同镜像号位置（手册第 3、14 章）。
7. 条码只有在镜像**使能了写条码功能**时才会写入芯片。

### 9.4 多台并联

8. 广播地址 `88888888` 适合"全体同时启动烧录"；**多台星形连接时不要用广播地址做查询**，否则回复会混乱。
9. 查询命令只有**目标编程器**会回复，非目标编程器静默。

### 9.5 固件与配置

10. `U` 命令需固件版本 **> 20240103000000**。
11. 固件升级后**不保证旧配置文件及编程器内镜像数据可用**（手册 11.2.4）——升级前务必保存好原始数据。
12. 串口命令触发方式需在电脑软件**"触发烧录方式选择"**（手册 11.2.1.7）中确认已启用"扩展串口命令"。

### 9.6 硬件与安全

13. 串口默认参数为 **9600-8-N-1**（波特率 9600、8 数据位、无校验、1 停止位）。
14. 转串口板需为 **FT232 或 CH340T 默认 VID/PID**，OEM 类不支持；优先带晶振版本。
15. **电源安全**：编程器可输出电源，除非必要不要再给目标板接额外电源，否则接错线可能造成电压串联叠加，损坏编程器或目标板（此类损坏不在保修范围，手册第 2 章）。

## 10. 原文勘误说明

手册中部分字段位号描述与实际示例不符，本协议按**实际示例**整理，实现时请以本协议为准：

- 启动命令：原文写"第 19-23 位为镜像号"、"从第 24 位开始为条码"，但示例（`` `P00881289000000010765... ``）中镜像号实际为 **4 位**（第 19-22 位），条码从第 23 位开始。
- 查询命令：原文写"第 11-17 位为通道掩码"，但示例中掩码为 **8 位**（第 11-18 位），`\n` 为第 19 位。
- 清除命令（`F`）一节原文误把非法字符列表写成 `'C'`（应为 `'F'`）。

## 12. 主机侧重试语义（BurnMachine SDK，M67/MC-01 关联批次补录）

BurnMachine SDK（BurnWorker）的异常重试会进行**完整时序重放**：打开串口失败、发送异常、轮询阶段 IO 异常等进入异常重试分支的失败，会重新执行「清除结果（F）→ 启动烧录（P）→ 轮询结果（C/U）」完整序列。**轮询超时不同：它返回终态 `BurnResultKind.Timeout`，不进入异常重试分支，也不重发 F/P。**后果与取舍：

- **同一芯片可能被烧录两次**——轮询阶段 IO 异常发生在烧录指令已发出之后，异常重试会重发 F+P；XW16Pro 的烧写计数/擦写寿命将被双扣。单纯轮询超时不会触发该重放。
- 取舍依据：对瞬时串口异常，重复烧录的代价低于直接判 NG；但轮询超时代表设备可能仍在烧录或已完成，必须作为终态返回，避免物理动作重放。
- 该整轮重放语义对**轮询 IO 异常**同样成立；如产线出现烧写计数损耗投诉，可改为「烧录指令已发出 → 异常时仅重新轮询、不重发 F/P」（审查 BM-01 案B）。
